# Session 241 · CMD-P36 家族四分面只读摘要

> 范围：S20 / S18 家族 UI 迁移第二步。只接同源读路径，不迁移生产写链，不修改 API、
> 引擎、规则、数值、RNG、Schema 或存档。

## 一、交付

命令坞“家族”从迁移说明升级为可用的 `总览｜姻亲｜婚配｜跟随` 四分面：

- **总览**：玩家势力历史女角、姻亲支、剧本固定子女登场数、在野候选数。
- **姻亲**：男将—正妻—固定子女关系及待/已登场状态。
- **婚配**：当前可婚历史女角与无正妻己方武将，只读列名。
- **跟随**：在野武将、所在地、相性差、仁德理想及血亲触发摘要；明确仍需邻接和权威 RNG。

派生函数 `buildFamilyOverview()` 仅消费客户端已收到的 `GameState` 与 `childrenCatalog`；
历史女角限定玩家势力，固定子女限定 `enabledChildEventIds`，不读取 S09 `beautyStock`。

## 二、迁移边界

- 命令坞家族内 `data-command-write="true"` 数量保持0。
- 旧 `FamilyPanel` 的婚配与手动跟随仍是唯一玩家写入口，各保留1个。
- 婚配、手动跟随、月度跟随、S11 登用关系同步、固定子女登场均未改动。
- P35 发现的 `giftedToOfficerId` 随侍随迁语义继续留待 P37 前拍板。

## 三、验证

- 四分面按钮与内容各1，命令坞新写入口0，旧婚配/跟随入口各1。
- 从旧面板完成蔡琰婚配后，新婚配候选数从1降到0，新姻亲分面立即出现荀彧支。
- `marry` 行动日志正确，浏览器 console error 为0。

纯模型测试覆盖玩家女角过滤、姻亲与固定子女、婚配候选、相性触发候选及敌方女角不泄露。

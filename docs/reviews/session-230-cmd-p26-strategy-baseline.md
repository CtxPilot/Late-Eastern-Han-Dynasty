# Session 230：CMD-P26 计略现状审计与可复现基线

> 范围：S20 / S17 既有计谋入口的迁移前审计。本轮只建立边界、迁移顺序和 Headless
> 基线，不把写操作接入命令坞，不删除旧入口，不改变规则、API、数值或存档。

## 一、结论

内政原子切换后，下一迁移域确定为**计略**。现有 S17 已有美人计、离间计、假情报、
空城疑兵四条正式写链和进行中记录，范围比情报与家族更集中，适合先迁。

计略迁移不能把左栏相邻组件整段搬运：

1. `PlotPanel` 四计属于 S17，是本域迁移对象；
2. `GrandStrategistPanel` 的总军师任免继续归朝廷；未来战略态势与献策才归计略；
3. `SpyPanel` 的探秘、女间谍和离间任务属于 S07 情报，即使会给美人计/假情报提供前置，
   也只能跨域导航，不能复制进计略表单；
4. 白刃战、六角计策与 Campaign Army 军令仍归 S10/S05，不进入大地图计略。

## 二、现有入口与权威写路径

| 旧命令 | 目标与前置 | 消耗 | store action → API | 终审 |
|---|---|---:|---|---|
| 美人计 | 敌城、detailed 情报；可选空闲女间谍 | 美女2、金150 | `launchPlot()` → `/plot/launch` | 已有统一终审 |
| 离间计 | 存活非己方、非盟友势力 | 金200 | 同上 | 已有统一终审 |
| 假情报 | 敌城、detailed 情报 | 金120 | 同上 | 已有统一终审 |
| 空城疑兵 | 己方城、兵力<3500、粮≥150 | 目标城粮150 | 同上 | 已有统一终审 |

服务端 `server/src/engine/plot.ts` 继续负责进行中上限、资源扣除、情报深度、盟友限制、
特工状态、权威 RNG、准备阶段和行动日志。客户端终审前已有部分最新快照复验，但美人计/
假情报的 detailed 情报、离间计盟友关系和进行中上限仍依赖服务端最终校验；迁移时应补齐
可从当前快照可靠判断的禁用原因，不能放宽服务端边界。

## 三、建议只读信息架构

后续计略抽屉固定为 `态势｜发起｜进行中`：

- **态势**：只读展示当前进行中数量/上限、势力资源、美女库存、已知 detailed 敌城、
  可用女间谍与空城候选；未来接总军师态势/献策，但不接任免。
- **发起**：承接四计草稿与唯一终审；探秘不足时只提供“前往情报”导航意图，不复制谍报命令。
- **进行中**：展示准备、生效、剩余月、识破与结果；中止/反制尚无权威规则，不提供假按钮。

建议 CMD-P27 先只接三分面与只读摘要，新写按钮保持0；CMD-P28 再迁四计写链并删除左栏旧
`PlotPanel`；CMD-P29 做跨情报导航、旧写 DOM=0 和四计总验收。

## 四、可复现浏览器基线

`pnpm verify-cmd-p26-headless` 固定 1440×900、英雄集结曹操局：

- 左栏旧 `PlotPanel` 和唯一 `btn-plot-launch` 均存在；
- 命令坞计略保持 `legacy`，写入口为0，并明确指向左侧旧面板；
- 实际选择离间计与目标势力，取消终审后总金和计谋数不变；
- 再次确认后玩家总金减少200，新增一条 `sowDiscord / prep` 计谋并写
  `plot_launch` 行动日志；
- 控制台 error 为0；任一入口数量、资源、状态或日志断言不符即失败。

## 五、范围边界

本轮只新增审计报告、仓库化 Headless 脚本和 package 命令。没有运行时组件、store、API、
引擎、规则、数值、RNG、Schema 或存档变化，也不宣称计略迁移已经开始。

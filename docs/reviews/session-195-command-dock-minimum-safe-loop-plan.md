# Session 195：大地图命令 UI 最小安全闭环迁移计划

> 范围：S20 前端体验；只规划“通用命令坞壳层 + 朝廷抽屉 + 统一终审”的首批渐进迁移。  
> 依据：`07-ui-design.md` §12、Session 190 信息架构审查、Session 191 高风险终审补丁、
> Session 194 体验问题收口及当前 React 实现。  
> 规划状态：**CMD-P0～P4 已于 Session 196～199 全部完成**。本文件保留原规划与验收口径；
> CMD-P5 已于 Session 202 完成，结论与下一域计划见
> `session-202-cmd-p5-next-domain-review-and-plan.md`；下一迁移域建议为人事（CMD-P6～P10）。

## 一、决策摘要

1. **现在启动渐进迁移，不继续扩充旧手风琴。**
2. 首个完整迁移域为**朝廷**；只迁当前已经实装的君主/HC-P0 能力，不借迁移新增称王、称帝、
   迁都、国策或新资源。
3. 先实现可复用的通用壳层，再以朝廷作为首个域；不做 `CourtDock` 之类一次性专用壳。
4. 现有 `CommandConfirmDialog` 是 §12“居中终审窗”的已验证雏形，应原位升级和复用，不另建
   第二套确认组件或提交路径。
5. 朝廷新入口通过验收后，在**同一发布切片**删除旧“君主”手风琴；不允许两个可提交入口长期共存。
6. 军事、人事、外交、计略、情报、屯田、家族、内政本批均不迁移；旧界面继续工作。底部九类位置
   可以完整出现，但未迁移类别必须明确显示“仍在原面板”，不得提供假命令或第二套入口。

预计为 **3 个常规 Session，风险缓冲后 2～4 个 Session**。工作量主要来自布局状态机、无重复入口
切换、终审语义统一和浏览器路径回归，不是单纯 CSS 调整。

## 二、§12 规格完整性审计

### 2.1 已足够明确、可直接作为实现约束的部分

| 主题 | 已确定规格 |
|---|---|
| 一级信息架构 | 固定九类：内政、军事、人事、外交、计略、情报、屯田、家族、朝廷 |
| 层次职责 | 命令坞选领域；侧边抽屉浏览状态、选择命令并配置参数；终审窗只负责复核与最终提交 |
| 命令可用性 | 随当前对象变化；不可用项置灰且展示具体原因，不能只隐藏 |
| 状态标记 | 可用 / 部分可用 / 设计中；禁止为了填菜单制作假入口 |
| 状态变更协议 | 配置参数 → 下达命令 → 终审；确认前不调用 API，取消保留参数 |
| 提交安全 | 提交中锁定；服务端失败保留窗口、参数及可操作错误；不提供“不再询问” |
| 风险语义 | 普通朱砂，宣战等重大行为深红；重大行为不可由 Enter 直接确认 |
| 非命令边界 | 系统菜单、地图工具、通知中心、只读浏览不进入命令终审 |
| 朝廷归属 | 势力政治阶段、政治资本、诏令、爵位/封赏、长期国策及官制总览归朝廷 |

### 2.2 实施前必须补齐的细节空白

这些空白不改变 §12 方向，本计划将其固定为首批实施契约：

#### A. 布局和响应式

- 命令坞位于 `GameLayout` 底部、地图与左右栏共同内容区之上，不能遮挡地图控制、事件窗或战斗场景。
- 桌面首批基准仍为既有 Headless 尺寸 `1440×900`；九类与独立“进行”必须在一行可见。
- 首批最低支持宽度定为 `1280px`。低于该宽度时命令坞允许水平滚动，抽屉使用视口宽度上限，
  不压缩按钮到不可辨识；移动端重排不在本闭环。
- 抽屉默认从命令坞上方/靠左内容区展开，桌面宽度建议 `360～420px`、最大高度不超过可用内容区；
  内部滚动，地图仍可观察。最终像素以 Session 184 的金石水墨视觉真源校准。

#### B. 壳层和抽屉状态机

采用单一状态模型，不把开关状态散落到各领域组件：

```ts
type CommandDomain =
  | 'civil' | 'military' | 'personnel' | 'diplomacy' | 'strategy'
  | 'intel' | 'farming' | 'family' | 'court';

type CommandShellState = {
  activeDomain: CommandDomain | null;
  activeCommand: string | null;
  draftByDomain: Partial<Record<CommandDomain, unknown>>;
};
```

- 点击同一领域：开/关抽屉；切换领域：关闭前一抽屉并清理其尚未提交草稿。
- 终审取消：回到原抽屉并保留草稿；关闭抽屉或完成提交：清除该命令草稿。
- 游戏重开、换剧本/势力、离开 world 场景：必须清空所有命令壳层状态，防止跨局草稿污染。
- 领域组件只创建命令草稿，不直接调用变更 API；最终提交仍调用现有 store action/API。
- 本批不把命令草稿写入权威 `GameState` 或存档；它是纯客户端瞬时 UI 状态。

#### C. 可访问性和焦点

- 命令坞使用可识别的导航/工具栏语义；按钮暴露选中、禁用和原因。
- 打开抽屉后焦点进入抽屉标题或首个可操作项；关闭后返回触发它的命令坞按钮。
- 终审窗打开时必须锁定焦点，关闭后回到“下达命令”按钮；背景不可操作。
- `Esc`：终审中仅返回抽屉并保留草稿；抽屉中关闭抽屉并清草稿。
- 危险命令不绑定 Enter 确认。现有对话框尚无焦点锁定/恢复，这是升级必做项。

#### D. 抽屉内容组织

朝廷抽屉采用同域分面，而不是再次纵向堆叠：

- **概览**：君主、政治头衔/阶段、汉帝控制状态、皇权、伪诏冷却；
- **诏令**：伪诏宣战；先选目标势力，再展示门槛与后果；
- **官制**：霸府官职占用情况和任职者只读概览；
- **大事**：开霸府；未来称王/称帝等只作为文档预留，不渲染假按钮。

首批不渲染尚未实装的威望、正统、国策、迁都等空数据。

### 2.3 规格结论

§12 的**架构方向、分类和安全协议完整**，无需重新拍板；但原文不够细到直接编码。上面的布局、
状态机、焦点、草稿生命周期和切换契约应在首个实施切片同步补入 `07-ui-design.md` §12，成为后续
军事/人事/外交迁移的共同基线。

## 三、最小安全闭环的精确范围

### 3.1 本批包含

#### 通用壳层

- `CommandDock`：九类固定入口 + 独立“进行”位置的布局壳。
- `CommandDrawer`：通用标题、状态标记、页签/分组区、滚动区、禁用原因区和底部动作区。
- `commandShell` 状态：领域、命令、草稿、关闭/切换生命周期。
- 未迁移类别的兼容状态展示；不复制旧面板内容。
- world 场景集成、事件/终审遮罩层级、`1440×900` 与 `1280px` 基线布局。

#### 朝廷域

- 迁移旧“君主”折叠项现有全部内容：
  - 君主姓名、政治头衔和政治阶段；
  - 是否控制汉献帝及开府门槛原因；
  - 皇权数值、伪诏冷却；
  - 开霸府；
  - 伪诏宣战的目标选择、禁用原因与后果预览。
- 官制页只读展示已实装霸府官职及任职者；“任命/调整”只创建到现有人事任命流程的导航意图，
  不在朝廷域复制 `appoint` API 或表单。
- 朝廷域所有状态来源继续读取当前 Zustand 中的权威游戏快照；不复制资源或规则计算。

#### 统一终审

- 升级现有 `CommandConfirmDialog`，使其既服务新朝廷抽屉，也继续兼容尚未迁移的旧入口。
- 开霸府和伪诏宣战继续调用现有 `establishHegemony()` / `falseDecreeWar()`；数值、门槛及服务端规则不改。

### 3.2 本批明确不包含

- **内政**：右栏农业/商业/城防/施米/寻访等保持原位；
- **军事**：战役编成、出征、Army 操作、郡域战场入口保持原位；
- **人事**：名册、搜索登用、任命、美女资源保持现有手风琴；霸府官职写操作仍归人事；
- **外交**：目标卡片、进贡、献美、点化、结盟保持现有手风琴；
- **计略、情报、家族、总军师**：全部保持现状；
- **屯田**：仍为设计中，不制作可点击入口；
- §12.5“进行/结束本月”完整汇总终审：命令坞先预留独立位置，但本批不改变 TopBar 现有推进逻辑；
- HC-P1/P2：称王、称帝、王国/帝国官职增强、国号、迁都；
- 移动端重排、快捷键/收藏/最近使用、全局对象选择器、动画系统和整体视觉重做；
- 服务端规则、API、存档 Schema 和权威 GameState 变更。

### 3.3 为什么必须先做通用壳层

直接做朝廷专用组件短期少一层抽象，但会把位置、开关、抽屉尺寸、草稿、焦点、终审交接再次写死在
朝廷内。后续迁军事/外交时仍须重构，且容易产生三套不一致提交协议。

通用壳层的范围刻意限制在**布局与交互协议**，不提前抽象各领域业务表单。这样既能让朝廷成为真实
首个消费者，也能让后续领域复用容器而不被朝廷数据模型绑住。

## 四、`CommandConfirmDialog` 的复用与升级

### 4.1 现状判断

它已经满足并实际验证：

- 居中模态、普通/危险色；
- 动态摘要和键值项目；
- 确认前不提交、取消返回；
- 提交中锁定并显示“传令中”；
- 服务端错误留窗；
- `Esc` 取消。

因此它就是 §12 终审窗的**雏形和唯一演进点**，不能另建 `CourtConfirmDialog`。

### 4.2 首批必须升级

- 为标题生成唯一 ID，避免多个挂载实例共享 `command-confirm-title`；
- 增加初始焦点、焦点圈定、关闭后焦点恢复；
- 明确 `closeOnBackdrop` 契约：首批保留背景点击返回，但 loading 时禁止；危险命令可配置为仅按钮/`Esc` 返回；
- 将任意 `items[]` 继续作为渲染层，同时引入可选的标准语义槽位或构建器：
  执行者、目标、立即/持续消耗、耗时、收益、概率、风险、不可逆后果；
- 支持 `confirmDisabled` 与可见原因，防止抽屉打开后权威状态变化仍可提交；
- 失败错误属于当前命令草稿；取消终审后可在抽屉中可见，关闭抽屉才清除；
- 保持现有调用点兼容，避免为了朝廷首迁同时重写 15 类高风险操作。

### 4.3 不应放进终审组件的职责

- 不读取 `GameState`；
- 不自行计算消耗、概率、冷却或门槛；
- 不调用 API/store action；
- 不持有领域草稿；
- 不决定某项业务是否危险。

业务域构建终审数据并提供提交回调；终审窗只保证展示、安全交互和一次提交。

## 五、过渡期与新旧入口策略

### 5.1 总原则：壳层可渐进，单个写入口不可双活

允许底部命令坞与旧手风琴在迁移期间同时存在，但**同一状态变更命令只有一个可操作入口**。

### 5.2 分阶段切换

1. **壳层开发态**：命令坞接入 world 布局；朝廷入口仅在测试开关下开发，生产旧“君主”入口不变。
2. **朝廷完整接线态**：新抽屉读取真实状态、开府/伪诏均走既有 store/API 和统一终审；旧入口仍只用于
   对照测试，不允许发布为双活。
3. **原子切换态**：同一提交/发布中启用新“朝廷”入口并删除旧 `AccSection·君主` JSX、相关本地确认
   分支和测试选择器。若新入口未通过验收，就不执行切换。
4. **切换后**：旧“君主”文字路径和 `btn-false-decree-*` 等选择器可保留兼容别名至测试脚本完成迁移，
   但 DOM 中不得保留可点击旧按钮。

### 5.3 官职边界

§12 已明确“官职属于人事，爵位由朝廷授予”。当前 `hegemonyPosition` 是霸府官职，不应因首迁朝廷
而复制任命逻辑：

- 朝廷“官制”负责势力级总览与发现；
- 写操作仍跳转到同一个 `AppointPanel`/未来人事抽屉；
- 在人事域尚未迁移时，跳转动作打开旧人事手风琴并定位任命区；
- 不在两个入口各维护一份候选人、门槛计算或确认窗。

### 5.4 测试路径影响

此前 Headless 多依赖“点击左栏君主 → 点击开霸府/伪诏”。切换切片必须同步：

- 改为“点击底部朝廷 → 大事/诏令 → 选择命令”；
- 优先使用稳定 `data-testid`，不依赖中文文本、DOM 层级或滚动坐标；
- 保留并重跑 HC-P0 原始玩家路径：董卓开府、皇权/冷却展示、伪诏取消/确认、霸府官职导航；
- 增加断言：页面不存在第二个开府/伪诏提交入口。

## 六、实施子任务与验收标准

### CMD-P0：规格固化与测试基线（文档/测试准备，0.5 Session）

**产出**

- 将本计划的状态机、响应式、焦点、草稿和切换规则补入 `07-ui-design.md` §12；
- 记录现有朝廷状态/命令的 UI 与 store action 映射；
- 为原 Headless 路径整理稳定选择器清单和切换前基线截图。

**验收**

- 朝廷每个展示字段、门槛、提交 action 都有唯一来源；
- 明确列出旧入口删除点和受影响测试；
- 零运行时代码行为变化，文档交叉引用无冲突。

### CMD-P1：通用命令坞壳层（1 Session）

**产出**

- 通用 `CommandDock`、`CommandDrawer` 和壳层状态/草稿接口；
- `GameLayout` world 场景接入；
- 九类稳定位置、状态标记、未迁移域兼容说明；
- 朝廷用占位测试内容验证容器，但不提交业务状态。

**验收**

- `1440×900` 九类与独立“进行”位置完整可见；`1280px` 不遮挡核心地图操作；
- 开关/切域/关闭草稿生命周期满足 §2.2；
- 未迁移域没有假按钮、没有复制旧面板；
- 事件窗、人物详情、战斗/郡域场景层级不受影响；
- typecheck、lint、build 及 Headless 壳层交互通过。

### CMD-P2：朝廷抽屉完整迁移（1 Session）

**产出**

- 概览/诏令/官制/大事四分面；
- 当前政治阶段、汉帝控制、皇权和冷却全部接权威快照；
- 开霸府与伪诏宣战建立命令草稿，门槛及禁用原因可见；
- 官制总览与现有人事任命唯一入口跳转。

**验收**

- 诸侯不控帝、诸侯控帝、霸府皇权不足、冷却中、已交战五类状态均展示正确；
- 伪诏目标使用单一选择器，不再按势力线性铺按钮；
- 官职任命没有第二套业务表单/API；
- 新抽屉尚未切生产入口前，所有 HC-P0 权威结果与旧路径一致。

### CMD-P3：统一终审升级与朝廷安全闭环（0.5～1 Session）

**产出**

- 原位升级 `CommandConfirmDialog` 的焦点、唯一标题、状态变化再校验和标准语义展示；
- 开霸府/伪诏从朝廷草稿进入同一终审；
- 保持其他 13 类左右既有调用点兼容（Session 191 合计 15 类高风险操作的口径不倒退）。

**验收**

- 取消后不调用 API、参数/目标保留；确认后只提交一次；
- loading 防重；服务端失败保留终审和草稿；
- 开府终审列出不可逆阶段变化/皇权100；伪诏列出目标/皇权40/战争/8季/潜在声望−30；
- `Esc`、焦点圈定与焦点恢复符合契约；危险操作 Enter 不提交；
- 现有高风险确认浏览器冒烟与相关全量测试无回归。

### CMD-P4：原子切换、旧入口下线与测试迁移（✅ Session 199 完成）

**产出**

- 生产启用“朝廷”命令坞入口；
- 删除左栏“君主”折叠及其本地提交/确认 JSX；
- 更新 Headless 脚本、选择器、截图和进度文档。

**验收**

- DOM 中开霸府、伪诏宣战各只有一个可提交入口；
- 董卓真实流程：朝廷→开府取消/确认→皇权100→选择目标伪诏取消/确认→皇权60、冷却8、关系war；
- 刘备/孙坚等不控汉帝势力显示具体门禁而非空白；
- 朝廷官制可到达人事任命，完成霸府官职任命后回到朝廷总览状态即时更新；

## 一、结论

**下一迁移域选择“人事”。**

优先级建议为：

1. **人事**：现在迁移；
2. **外交**：人事完成后迁移；
3. **军事**：第三顺位，先维持现有流程稳定。

理由不是人事最重要，而是它已经出现最明确、最持续的容量失效：名册、搜索/登用、任命、美女资源
纵向堆在 240px 窄栏内，Session 190 在 900px 高度下已证实仅名册就占满主要视口。它同时具备
适合第二个试点的条件：业务边界清楚、已有统一终审、朝廷官制已经通过“只读总览→跳转人事唯一写入口”
建立了真实依赖，迁移后可立即消除一条过渡桥。

本批建议编号为 **CMD-P6～P10**，保持“基线→读路径→写路径→跨域联动→原子切换”的五步结构。

## 二、朝廷域迁移复盘

### 2.1 符合预期的环节

| 环节 | 实际结果 | 可复用结论 |
|---|---|---|
| 先固化规格和基线 | CMD-P0 先记录旧入口字段、action、选择器和截图，P4 才能做功能对等核验 | 每域迁移前必须先建立“字段—规则—写 action—测试路径”清单 |
| 通用壳层先行 | `CommandDock`、`CommandDrawer`、草稿 reducer 未绑定朝廷模型，后续域可直接复用 | 壳层只管布局、焦点、领域和草稿生命周期，不吸收业务规则 |
| 数据同源交叉验证 | P2 新旧入口都读同一 Zustand `game` 快照，交替开府/伪诏可立即互相反映 | 过渡期可以短暂双入口验证，但不得创建第二份业务缓存 |
| 终审原地升级 | `CommandConfirmDialog` 兼容既有高风险调用点，并统一补焦点圈定、标题和再校验 | 共享安全能力应升级唯一组件，不为领域另造弹窗 |
| 跳转而非复制 | 朝廷官制只读展示，任命仍跳到唯一 `AppointPanel` | 跨域入口只传导航意图/对象，不复制候选、门槛和提交逻辑 |
| 原子切换 | P4 同一提交删除旧君主 JSX、旧 action 绑定并迁移 Headless 路径 | 壳层可渐进共存；同一命令的生产写入口不可长期双活 |

### 2.2 比预期更耗时的环节

1. **终审共享面大于朝廷本身。**
   P3 的改动触及 15+ 类既有操作，实际成本来自逐调用点补最新状态校验、焦点恢复与标题语义，
   而非弹窗样式。以后每域接入前应先盘点该域终审调用点，避免把共享安全升级夹进业务迁移。

2. **Headless 路径需要仓库化。**
   早期浏览器验证多为会话临时脚本，P4 才新增可重复执行的
   `verify-cmd-p4-headless`。后续域从 P6 起就应建立仓库内基线，不能等切换时再补。

3. **过渡导航会形成临时依赖。**
   朝廷“前往人事·任命”仍需打开旧人事手风琴。它没有复制业务，但意味着下一个域切换时必须
   同步改造朝廷跳转，否则会留下失效路径。

4. **“原子切换”需要显式负断言。**
   仅验证新入口可用不足以证明切换完成；P4 额外断言旧 DOM 和旧选择器数量为 0 才排除了
   CSS 隐藏、静默跳过和双写入口。

### 2.3 比预期更简单的环节

- 服务端规则和 API 基本无需迁移；前端新入口继续调用既有 store action。
- 权威状态已经集中在同一游戏快照，未发生新旧入口状态分叉。
- 通用抽屉的尺寸、动画、Esc、焦点和草稿清理契约已经稳定，后续不必再次设计。
- `CommandConfirmDialog` 已完成共享升级，下一域主要工作是提供领域草稿、终审摘要和
  `validateBeforeConfirm()`，而不是重做安全基础设施。

## 三、后续域通用迁移 Checklist

以下清单应作为 CMD-P6 及后续每个领域的固定入口条件。

### A. 迁移前

- [ ] 列出旧入口的只读字段、表单状态、禁用原因、store action/API 和所有终审调用点。
- [ ] 记录真实 Headless 路径、关键截图、成功/取消/失败后的权威状态。
- [ ] 搜索重复入口与跨域跳转；确定每个写操作迁移后的唯一归属。
- [ ] 区分权威状态、可派生 view-model 与纯客户端草稿，禁止复制规则或资源聚合。
- [ ] 明确本批不迁移内容及旧入口保留边界。

### B. 接线期

- [ ] 复用 `CommandDrawer` 和草稿 reducer，不增加领域专用壳层。
- [ ] 抽屉按同一任务流分面，不把旧面板整段搬进更宽容器。
- [ ] 目标/候选/门槛使用 shared 或既有服务查询；非法选项优先在参数阶段过滤。
- [ ] 所有写操作继续调用原 store action/API；终审使用唯一 `CommandConfirmDialog`。
- [ ] 跨域能力使用导航意图传递对象/子页签，不复制写表单。
- [ ] 新旧入口短暂交叉测试时，两边必须读取同一权威快照，不各持业务缓存。

### C. 切换与验收

- [ ] 新入口逐项对照旧基线：取消不提交、确认结果相同、失败保留草稿且原因可操作。
- [ ] 状态变化后终审重新校验，禁止发送过期请求。
- [ ] 同一提交删除旧 JSX、旧 action 绑定、旧本地状态与旧选择器。
- [ ] Headless 脚本迁移为稳定 `data-testid`，缺元素必须抛错，禁止条件跳过。
- [ ] 加入负断言：旧入口 DOM=0、同一命令可提交入口=1。
- [ ] 重跑专项、全量测试及 1440×900 实际流程；记录控制台错误数。

## 四、候选域评估

| 维度 | 人事 | 外交 | 军事 |
|---|---|---|---|
| 当前容量压力 | **高**：四类工作流纵向堆叠，900px 已失效 | 中高：目标势力卡片×多按钮线性增长；当前 0-A 仅 3 目标尚未形成压力实证 | 中：编成表单复杂且窄；另有右栏军事与郡域入口语义分裂 |
| 已有问题证据 | Session 190 P1-1；Session 200 名册规模边界未真正覆盖 | Session 190 P1-2；Session 192 结盟门禁曾失配，已修 | Session 190 P1-3；Session 200 非邻接目标已在 Session 201 修复 |
| 业务稳定性 | 较高：名册、搜索/登用、任命、赏赐均已有路径 | 中：未来停战、求援、借道等尚未实装，容易迁移后继续扩模型 | 较低：Campaign Army、右栏简化出征、郡域战场和未来四层战争仍在演进 |
| 与朝廷首迁联动 | **强**：官制跳转目前直接依赖旧人事入口 | 中：伪诏目标选择未来可复用势力选择器 | 中：暂无必须立即解除的临时依赖 |
| 迁移收益/风险 | **高收益、中风险** | 高收益、中风险 | 高收益、高风险 |

### 4.1 人事为何第一

- 当前问题是已发生的可达性缺陷，不是仅凭 0-B 推测的未来风险。
- 人事天然适合“任务页签”范式：名册、招贤、任官、赏罚各自有清楚边界。
- 可以验证通用壳层是否真能承载比朝廷更重的列表和表单，而无需同时碰战役状态机。
- 完成后朝廷“官制→任命”可从临时旧手风琴跳转升级为正式跨抽屉导航，验证壳层跨域复用。

### 4.2 外交为何第二

外交的目标列表×动作矩阵确实会随势力数线性膨胀，最终应采用“先选势力，再看关系/条约/行动”。
但当前 0-A 只有三个对手，Session 200 未观察到真实性能或可用性崩溃；而未来外交动作集合尚未齐全。
在人事迁移中先沉淀通用的搜索列表、对象选择和跨域导航模式，可降低外交迁移成本。

### 4.3 军事为何第三

军事布局问题真实存在，但它跨越城市驻军、Campaign Army、战役目标、郡域战场和未来四层战斗。
Session 193/201 刚收口敌我判定、Army 回写和目标过滤，当前流程稳定。过早迁移容易把仍演进的
军事业务边界固化进抽屉。应先单独完成“军事命令模型和三入口归并审计”，再开始 UI 切换。

## 五、CMD-P6～P10：人事域迁移计划

### CMD-P6：人事现状审计与可复现基线（0.5 Session）

**产出**

- 建立旧人事入口清单：名册/筛选/详情、搜索、登用、任命各轨道、美女资源/赏赐；
- 明确每项权威来源、草稿、门槛、终审标题、store action/API；
- 建立仓库内 Headless 基线，覆盖 1440×900 顶部/底部滚动、取消/确认和错误状态；
- 固化人事抽屉分面：`名册｜招贤｜任官｜赏罚`；“调动”未实装则只标设计中，不做假入口。

**验收**

- 旧入口每个可提交操作均有对应断言，不能只截图；
- 记录朝廷官制跳转与人物简册入口的目标语义；
- 零运行时行为变化。

### CMD-P7：名册与只读浏览接入（0.5～1 Session）

**产出**

- 人事抽屉接入名册、排序/筛选、在职/在野摘要和人物详情；
- 列表区独立滚动，详情继续复用现有 `OfficerDetail`，不复制四页签；
- 对大名单建立至少 100/1000 条合成数据的渲染基准或组件夹具，诚实区分于 0-A 实际数据。

**验收**

- 1440×900 无需滚过其他工作流即可完成筛选→打开详情→返回名册；
- 10 名实际数据与大名单夹具均无重复 key、重叠或焦点丢失；
- 本阶段不出现搜索/任命第二套写入口。

### CMD-P8：招贤写流程迁移（1 Session）

**产出**

- 搜索与登用进入人事草稿；候选、概率、消耗、执行者门槛复用现有规则；
- 接入统一终审和提交前再校验；取消保留草稿，成功清除；
- 搜索结果、在野候选和失败错误归属当前“招贤”分面。

**验收**

- 无可用执行者/无在野候选/资源不足时禁用并显示原因；
- 搜索、登用的取消/成功/失败与旧基线权威结果一致；
- 旧入口仍仅作为测试对照，不引入独立业务缓存。

### CMD-P9：任官、赏罚与跨域导航迁移（1～1.5 Session）

**产出**

- 迁移文官/地方官/武官/霸府官职任命，继续复用同一 appoint 引擎；
- 迁移当前已实装的赏赐/美女资源操作；未实装的没收、俘虏录用不做假按钮；
- 朝廷“官制→前往人事·任命”改为打开命令坞人事域并定位“任官”，可携带官职轨道意图；
- 人物详情中的人事快捷入口同样创建导航意图，不复制表单。

**验收**

- 同一官职唯一、阶段门槛、君主特例、资源与人员状态在送审前/确认前均重校验；
- 朝廷→人事跳转后只存在一份候选和提交逻辑；
- 旧人事入口和新抽屉交替操作时权威状态即时一致。

### CMD-P10：原子切换、旧入口下线与路径迁移（✅ Session 213 完成）

**产出**

- 同一提交删除旧“人事”手风琴及其本地表单/确认分支；
- 新人事抽屉成为名册、招贤、任官、赏罚唯一入口；
- 迁移全部 Headless 选择器和朝廷/人物详情导航路径；
- 更新 `07-ui-design.md`、相关人事规则/API 文档、进度和 HANDOFF。

**验收**

- 旧“人事”DOM=0，不是 CSS 隐藏；每类写命令可提交入口恰为 1；
- 基线全部在新路径重跑，找不到选择器或候选时必须失败，不得静默跳过；
- Headless 完成“名册→详情→搜索/登用→任官→朝廷官制往返”完整流程，控制台错误 0；
- client/shared/人事确定性/存档/全量 verify/typecheck/lint/build 全绿。

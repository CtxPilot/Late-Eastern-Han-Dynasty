# Session 226：CMD-P22 内政现状审计与可复现基线

> 范围：S20 / S03、S09 既有右栏入口的迁移前审计。本轮只建立边界、迁移顺序和
> Headless 基线，不把写操作接入命令坞，不删除旧入口，不改变规则、API、数值或存档。

## 一、结论

下一迁移域确定为**内政**，但右栏“内政操作”的五个按钮并不属于同一业务系统：

1. `开发农业 / 开发商业 / 修筑城墙 / 施米` 是 S03 城市经营；
2. `寻访` 的路由虽仍名为 `/civil/seek-beauty`，业务真源却是 S09
   `server/src/engine/beauty.ts`，会改变势力美女库存与城市可寻次数；
3. 征兵、训练已在 CMD-P20 归入“军事·军备”，不得重新复制进内政；
4. 屯田仍是独立一级域且未实装，农业开发不能改名冒充民屯。

因此 CMD-P22 后可以先做不涉及归属争议的内政只读城市总览；进入写链迁移前，必须单独拍板
S09“寻访”是作为内政跨系统任务保留，还是等待 S09 宫廷人脉入口，不能仅凭旧路由归类。

## 二、现有入口与权威写路径

| 旧按钮 | 系统归属 | 门槛与效果 | store action → API | 终审现状 |
|---|---|---|---|---|
| 开发农业 | S03 | 己方城、100金；农业 +20～30，上限999 | `develop('farm')` → `/civil/develop` | 无，点击即提交 |
| 开发商业 | S03 | 己方城、100金；商业 +18～28，上限999 | `develop('commerce')` → `/civil/develop` | 无，点击即提交 |
| 修筑城墙 | S03 | 己方城、120金；城防 +15～25，上限999 | `develop('wall')` → `/civil/develop` | 无，点击即提交 |
| 施米 | S03 | 己方城、150粮；民心 +8～12，上限100 | `relief()` → `/civil/relief` | 无，点击即提交 |
| 寻访 | **S09** | 己方城、60金、可寻次数≥1；权威 RNG 决定库存+1/可寻−1 | `seekBeauty()` → `/civil/seek-beauty` | 无，点击即提交 |

`/civil/develop-farm` 和 `/civil/search-beauty` 是兼容路由，当前玩家 UI 不直接调用。五项
旧按钮都依赖 `selectedCityId`，没有自己的城市草稿，也没有 `CommandConfirmDialog`。

## 三、迁移边界

- 内政抽屉建议按现有正式能力先形成 `总览｜产业｜城建｜赈济`；未实装的手工业、交通、
  卫生、教育、税率、设施与道路只写设计说明，不提供假按钮。
- “修筑城墙”当前实际增加 `City.stats.wall`，不是恢复战役城墙耐久；迁移 UI 应使用
  “城防开发”语义，不能与未来“修缮”混名。
- S03 四条写链迁入时应补统一终审、显式选城和确认前最新状态复验；旧入口无取消能力是本次
  记录的现状，不是需要兼容保留的安全契约。
- “寻访”不得与 S03 四条写链一起机械搬运；它消费 S09 权威 RNG、势力库存和城市额度。
- 征兵/训练继续只在军事抽屉；屯田继续保持设计中。

## 四、可复现浏览器基线

`pnpm verify-cmd-p22-headless` 固定 1440×900、英雄集结曹操局：

- 命令坞内政保持 `legacy`，业务写入口为0；
- 右栏五个旧按钮各恰为1，且点击后不出现终审，直接写入权威状态；
- 洛阳实际依次执行农业、商业、城防、施米与寻访；
- 本次实测农业+23、商业+26、城防+17、民心+11；寻访耗金60并成功，库存+1、额度−1；
- 五类行动日志齐全，控制台 error 为0；任一元素、区间、资源或日志断言不符即失败。

- **CMD-P25**：在 S09 寻访归属拍板后处理跨系统入口，并完成右栏旧内政原子切换总验收。

# HC-P1 称王设计与实施规划

> 系统归属：S08 外交 / S11 人事 / S12 官职爵位的既有深化。
> 上游：`docs/26-hegemony-court-design.md` 已批准 Q1～Q11，HC-P0-1～6 已完成。
> UI 前提：CMD-P4 已下线旧“君主”手风琴；HC-P1 从第一天起只接底部命令坞“朝廷”抽屉。
> 本文状态：K1～K8 已批准；**HC-P1-1 门槛地基、HC-P1-2 称王状态转移与王号已实装**，
> **HC-P1-3 王国官职已实装**，HC-P1-4～6 待实施。

## 一、设计结论

HC-P1 采用严格线性、不可逆状态转移：

```text
诸侯 vassal
  → 控制汉帝并开霸府
霸府 hegemon
  → 规模 + 时间沉淀 + 皇权门槛 + 玩家终审
王 king
```

推荐初始门槛：

```text
城池数 ≥ max(3, ceil(当前剧本纳入争夺的总城池数 × 25%))
且霸府阶段已维持 ≥ 12个月（4季）
且 imperialAuthority ≥ 80
且 politicalStage === 'hegemon'
```

称王确认后：

- `politicalStage = 'king'`；
- `politicalTitle = '{王号}王'`，王号首次确定后固定；
- 消耗皇权 80，保留余额；
- 启用已预留外交档：结盟 `+8` 百分点、进贡/献美友好增量 `×1.2`；
- 解锁 6 个王国官职；
- 解锁“王命封爵”，臣属爵位上限由侯提升到公；
- 霸府已有三官职与伪诏宣战继续有效，不清空任职者、不重置冷却。

“王国官制 + 王命封爵”是 king 阶段的专属机制，不只是霸府数值加大。

## 二、前置条件门槛

### 2.1 城池规模：相对比例 + 绝对下限 + 剧本覆写

推荐统一函数：

```ts
kingCityThreshold =
  scenario.kingRequirements?.minCities
  ?? Math.max(3, Math.ceil(contestableCityCount * 0.25));
```

其中：

- `contestableCityCount` 取当前剧本 `startState.cityOwnership` 中纳入争夺的城市总数；
- 不使用全项目 105 城或数据字典全量规模；
- 不按当前存活势力数动态变化，避免灭国后门槛漂移；
- `scenario.kingRequirements.minCities` 是可选调参覆写，不是每个剧本必须重复配置。

当前 0-A 两剧本示例：

| 剧本 | 纳入争夺城市 | 默认公式 | 实际建议 |
|---|---:|---:|---:|
| 190《关东义兵》技术切片 | 7 | `max(3, ceil(7×25%)) = 3` | 3 城 |
| 英雄集结 0-A Demo | 30 | `max(3, ceil(30×25%)) = 8` | 8 城 |

这满足 Q6 的剧本相对化方向：190 一城诸侯需扩张到 3 城；英雄集结的 3～5 城势力需扩张到 8 城。
曹操在英雄集结开局已有 17 城，会立即满足**规模**条件，这是该剧本“开局即高光”的既定设定，
不能靠把比例抬到 60% 来惩罚；时间和皇权门槛负责阻止开府后立即称王。

### 2.2 不采用总兵力硬门槛

HC-P1 初版不建议同时要求固定总兵力：

- 兵力随出征、伤亡和驻军回写高频波动，可能出现已具王国规模却因一次战损按钮忽明忽暗；
- 190 与英雄集结的每城兵力密度不同，绝对数会再次破坏剧本相对化；
- 城池规模已经表达稳定领土，时间与皇权表达政治沉淀。

若实测发现“空城速推”可滥用，再增加相对化的守备条件，例如
`势力总兵力 ≥ 3000 × kingCityThreshold`，而不是先塞入未经验证的 30,000/50,000 常量。

### 2.3 时间沉淀：霸府维持 12 个月

推荐增加可序列化的阶段年龄：

```ts
Faction.politicalStageAgeMonths?: number;
```

- 开府、称王、称帝转移时重置为 0；
- 每次完整结束月份后，对非 `vassal` 势力 +1；
- 旧存档缺失时按 0 处理；
- 称王要求 `>= 12`，即 4 季；
- 不只使用 `politicalStageChangedYear`，否则十二月开府到次年一月会被误判“已满一年”。

12 个月足以形成战略等待，又不会让 Demo 必须推进多年。UI 应显示“霸府沉淀 7/12 月”，不能只给
一个禁用按钮。

### 2.4 皇权门槛与消耗

推荐：

- 送审门槛：`imperialAuthority >= 80`；
- 确认后消耗 80；
- 不改变 HC-P0 的 100 上限和季度 +10 恢复；
- 伪诏宣战仍消耗 40、冷却 8 季。

它形成清楚取舍：频繁伪诏会推迟称王；长期积蓄皇权才能推进政治阶段。由于开府初始即有 100，
时间门槛仍不可省略。

### 2.5 完整前置校验

称王只在以下条件全部满足时可送审，并在终审确认前以最新权威快照再次校验：

1. 势力存在且存活；
2. `politicalStage === 'hegemon'`，`vassal` 不得跳级，`king/emperor` 不得重复；
3. 城池数达到本剧本门槛；
4. 霸府阶段年龄达到 12 月；
5. 皇权不少于 80；
6. 已取得合法王号且未被其他存活势力占用（若启用唯一性规则）；
7. 当前没有另一项提交中的朝廷大事。

称王**不再要求此刻继续控制汉帝**。控制汉帝是“开霸府”的资格；称王是霸府发展后的下一阶段。
若开府后汉帝所在地失守，玩家仍可完成称王，但失去依赖汉帝控制的其他能力应由各能力自身校验。

## 三、称王专属收益

### 3.1 王国官职扩展

沿用 Q2 已批准的独立 `hegemonyPosition` 轨道。霸府三职继续保留，king 新增 6 职：

| 建议 ID | 显示名 | 定位 | 初始门槛方向 |
|---|---|---|---|
| `kingdomChancellor` | 王国相 | 百官总领、综合政务 | 政≥85、智≥80 |
| `kingdomInteriorMinister` | 内史 | 国都与内政 | 政≥80、魅≥70 |
| `kingdomCommandant` | 中尉 | 王都宿卫与治安 | 统≥80、武≥75 |
| `kingdomGentlemanSteward` | 郎中令 | 宫卫与近臣 | 统≥75、魅≥75 |
| `kingdomAgricultureMinister` | 大司农 | 财粮与屯储 | 政≥80、智≥75 |
| `kingdomCoachMinister` | 太仆 | 马政与交通 | 统≥75、政≥70 |

规则：

- 六职均为势力唯一，只有 `king/emperor` 阶段可任命；
- 霸府三职不自动替换、不强制撤任；王国官职是扩展层，不是破坏性升级；
- 相同人物能否同时持霸府职与王国职沿用“独立轨道最多一个值”的现状：同一
  `hegemonyPosition` 只能选一个，任命新职会替换旧职；
- HC-P1 先实现任职资格、唯一性、展示和基础编成/俸禄联动；复杂专属被动可后调参。

### 3.2 王命封爵

称王后解锁“王命封爵”作为朝廷域专属能力：

- 对非君主、同势力、在职武将授予/晋升臣属爵位；
- HC-P1 臣属最高只到“公”，不得把臣属封为“王”或“皇帝”；
- 每次封爵进入统一终审，展示受封者、旧爵/新爵、皇权或声望消耗；
- 初版建议消耗皇权：侯阶晋升 10、公爵晋升 20；一次只升一级；
- 爵位终身制的既有设计意味着不可撤销，使用深红/重大终审语义。

这是 king 独有的新写能力。霸府阶段只能任命霸府官职，不能主动把臣属晋至公爵。

### 3.3 外交分档启用

无需重新设计公式，直接启用 HC-P0-5 已预留值：

- `hegemonyAllianceModifier('king') = +8`；
- `hegemonyFavorMultiplier('king') = ×1.2`；
- 仍只修正发起方；
- 不在 HC-P1 引入“对汉室态度匹配修正”，避免和 HC-P0-6 的条件声望惩罚重复。

### 3.4 伪诏与皇权

HC-P1 初版不增强伪诏数值：

- 消耗仍为 40；
- 冷却仍为 8 季；
- 皇权恢复仍为每季 +10、上限 100。

原因是称王本轮已有官制、封爵与外交三类收益；若同时缩短伪诏冷却，会把 HC-P1 平衡风险混入
状态转移验收。称王后的伪诏增强可作为独立调参子项，而非称王完成条件。

## 四、王号与头衔

### 4.1 数据承载

沿用 Q7：

```ts
Faction.politicalTitle = `${kingdomName}王`;
Faction.kingdomName?: string; // 首次称王时写入并固定
```

不修改 `rulerId` 或 Officer 实体。`kingdomName` 与势力显示名分离，用于未来国号、日志和称帝承接。

### 4.2 命名规则

推荐“剧本策划配置优先，地理回退”：

1. `ScenarioFactionSetup.preferredKingdomName?` 提供史实/角色化建议；
2. 若未配置，按称王时首都所属州郡映射到稳定的传统单字/地域号；
3. 若仍无法映射，取势力名去掉“军/政权/势力”等后缀；
4. 称王终审前允许玩家从**策划提供的有限候选**中选一个，不允许自由文本；
5. 确认后写入 `kingdomName`，迁都或失地不自动改王号。

0-A 建议配置：

| 势力 | 首选王号 | 说明 |
|---|---|---|
| 曹操 | 魏 | 历史封魏王，辨识度最高 |
| 刘备 | 汉中 | 历史称汉中王；避免与汉帝国国号混淆 |
| 孙权 | 吴 | 地域与后续国号一致 |
| 吕布 | 温 | 取其温侯既有称号，作为 Demo 策划映射 |
| 董卓 | 凉 | 取凉州集团背景；是否允许其称王留开放问题 |

王号唯一性建议只在同一运行局的存活势力之间校验；冲突时 UI 提供候选二，不自动加数字或君主姓氏。

## 五、状态转移与权威写路径

### 5.1 同构引擎流程

复用 `establishHegemony` 模式，新增集中式纯校验与状态转移：

```text
getKingRequirements(state, factionId)
  → 返回每项门槛、当前值、是否通过、王号候选

proclaimKing(state, factionId, kingdomName)
  → 再校验
  → 扣皇权 80
  → politicalStage = 'king'
  → politicalTitle = `${kingdomName}王`
  → kingdomName = kingdomName
  → politicalStageChangedYear = currentYear
  → politicalStageAgeMonths = 0
  → actionLog 记录称王、王号、领土规模与皇权消耗
```

服务层、API 和 store 只编排这一权威函数，不在 UI 重写门槛。存档字段继续 optional 追加并做旧存档
往返；若新增剧本配置，必须先扩对应 Zod，再改 JSON。

### 5.2 失败原子性

任何前置失败、王号冲突或提交重复都不得部分扣皇权、改头衔或解锁官职。状态转移应先完整校验，
再对克隆/不可变快照一次写入；日志只在成功后追加。

### 5.3 AI 边界

HC-P1 先提供引擎能力，但不让 AI 自动称王。AI 何时使用称王、如何响应玩家称王属于 S15 深化，
需另行设计；测试可以直接调用权威函数验证非玩家势力，不等于 AI 已有决策。

## 六、朝廷抽屉集成

称王从一开始只接新架构：

### 概览

- 显示当前阶段、政治头衔、王号（若有）、皇权；
- 霸府阶段显示“称王进度”：城池 `当前/门槛`、沉淀月份 `当前/12`、皇权 `当前/80`；
- 已称王后显示已启用外交档和王国官制摘要。

### 大事

- 新增“称王”命令；
- 未满足时按钮禁用并逐条显示原因，不只用 `title`；
- 满足后创建 court 草稿：王号、门槛快照、皇权消耗；
- 统一终审标题示例：`确认称王：曹操 → 魏王`；
- 终审明确写“不可撤销”“消耗皇权80”“政治阶段变为王”“解锁王国官制与封爵”；
- `validateBeforeConfirm()` 使用最新游戏快照再次调用同一门槛查询。

### 官制

- 朝廷继续只读展示霸府/王国官职和任职者；
- “前往人事·任官”跳转到 CMD-P5 选定的未来人事抽屉；在人事尚未迁移完成前，保持当前唯一
  `AppointPanel` 路径，不在朝廷复制表单。

### 爵位

- 王命封爵属于朝廷写操作，使用人物选择器和统一终审；
- 人事域只读展示人物爵位，不能另建第二个封爵按钮。

## 七、实施拆分与验收

### HC-P1-1：称王门槛与阶段年龄地基

**产出**：剧本相对门槛查询、`politicalStageAgeMonths`、可选剧本覆写字段、Zod/存档迁移。
**验收**：190=3城、英雄集结=8城；月份推进/阶段重置准确；旧存档按0月降级；非法配置拒绝。

**实施状态（Session 203 · 已完成）**：

- `getKingRequirements(state, factionId)` 为只读权威查询，按剧本开局
  `cityOwnership` 固定争夺城市总数；返回势力存在/存活、霸府阶段、城市、阶段年龄、皇权各项
  `current/threshold/passed` 与总通过状态；
- `Faction.politicalStageAgeMonths?` optional 追加，不升 schema 版本；开府归零，
  非 `vassal` 势力每次完整月结后 +1，旧档缺失查询按0、首次月结从0推进到1；
- `ScenarioStatic.kingRequirements?.minCities` optional 追加；Zod 要求严格对象内的正整数；
- 专项 `pnpm verify-hc-p1-1` 15/15，覆盖 190=3、英雄集结=8、剧本覆写、阶段重置/月进、
  旧档降级与非法配置拒绝；
- 边界不变：未实现称王状态转移、王号、王国官职或爵位收口。

### HC-P1-2：称王状态转移与王号

**产出**：王号配置/回退、`kingdomName`、`proclaimKing`、API/store、日志。
**验收**：仅 hegemon 可转移；前置失败零副作用；成功扣80皇权并写 king/头衔/王号/年龄0；

- `getKingdomNameCandidates` 按剧本配置→首都所属州传统号→势力名去后缀生成去重有限候选，

- 专项 `pnpm verify-hc-p1-2` 36/36，覆盖五项配置、候选回退、逐项前置错误、唯一性候选二、

### HC-P1-3：王国官职

**产出**：6 个王国官职、阶段/属性/唯一性门槛、任命与人物详情展示。
**验收**：hegemon 拒绝、king/emperor 可任；势力唯一；替换同轨官职不产生重复；既有三职不丢失。

**实施状态（Session 205 · 已完成）**：

- `HegemonyPosition` 同一单值轨道追加六职及标签/门槛，不新增 Officer 字段、不升存档版本；
- `appointOfficer` 区分霸府三职与王国六职：hegemon 任王国职给出“需先称王”，king/emperor 可任；

  不扫描或撤销既有三职；
- 既有 AppointPanel 按阶段过滤候选，OfficerDetail 将该单值统一标为“朝职”；朝廷官制总览仍留
  HC-P1-5；
- 专项 `pnpm verify-hc-p1-3` 41/41 覆盖六职枚举/精确门槛、hegemon 拒绝、king/emperor

## 八、开放问题（实施前拍板）

### K1 门槛公式

是否批准 `max(3, ceil(剧本争夺城市×25%))`，当前两剧本分别为 3/8 城？

**推荐：批准。** 它满足相对化，又避免 7 城小剧本只需 2 城。

### K2 时间与皇权

是否批准霸府满 12 个月、皇权至少80且称王消耗80？

**推荐：批准。** 三者分别表达领土、政治沉淀和资源取舍；不加时间会使英雄集结曹操开府后立即称王。

`hegemonyPosition` 轨道只能持其中一职。

**推荐：批准。**

### K6 爵位枚举语义债

当前代码枚举为 `none/marquis/duke/prince/king`，UI 映射为侯/公/王/皇帝；而设计文档又描述
7 级 `关内侯→亭侯→乡侯→县侯→公→王→皇帝`，存在明确不一致。HC-P1-4 应：

- A. 先迁移到完整 7 级枚举，再实现封爵；
- B. 保留 5 级运行时，把 `prince` 视为王、`king` 视为皇帝，仅做标签澄清。

**推荐 A。** 称王与臣属封爵会直接放大该歧义，继续兼容旧口径只会把数据债带入存档。
这属于 HC-P1 的必要地基，但必须单独迁移、提供旧存档映射，不能顺手改枚举。

## 一、设计阶段定位

本文档**只做审计与设计**，比照 BF-P0~P2 模式：先查清前置系统现状（§二），再产出设计文档（§三~§七），列出开放问题清单（§八）等用户拍板，拍板后才进入实施。理由与 BF-P0~P2 一致：本主线会牵动官职系统（S12）、外交系统（S08/S17）、君主身份机制、"对汉室态度"独立化四个已有或正在讨论的系统，量级接近 BF-P0 级别的新主线，盲写代码会引发跨系统返工。

### 1.1 非目标

- 不写实现代码、不改任何现有数据结构（`Faction` / `Officer` / `DiplomacyLink` 等字段均不动）。
- 不在本轮启动城市设施构想（已登记于 `HANDOFF.md` §6.7，排在本文档拍板完成后）。
- 不引入新大系统编号（仍属 S08 外交 / S11 人事 / S12 官职功绩体力的既有深化，不新增 S24+）。
- 不在本轮拍板"对汉室态度"最终承载形式（tag vs 结构化状态机是开放问题 Q5）。
- 不变更现有剧本的开局势力设定（190 剧本四槽技术切片保持不变）。

### 1.2 与君主身份特例的关系

Session 188 已定稿君主身份特例规则（04 §3.8）：君主不参与忠诚度/拉拢记录/功绩系统，`Faction.rulerId` 开局后不可变，身份转变机制当前不存在。本主线**首次真正需要实现"身份转变"这个此前被认为"过度设计"而搁置的机制**——开霸府/称王/称帝如果伴随君主头衔变化（"曹操"→"魏王"→"魏帝"），就涉及 `Faction.rulerId` 指向的武将实体是否变化、头衔字段如何承载等问题。这是本主线对已有架构的最大冲击点，详见 §四接口设计。

## 三、进阶路线状态机设计

### 3.1 四阶段定义

| 阶段 | 名称 | 准入条件（必要） | 可获得能力类别 | 可停留 | 可后退 |
|:----:|------|------|------|:----:|:----:|
| 0 | **诸侯**（默认） | 开局即此状态 | 现有全部能力 | ✅ | — |
| 1 | **霸府**（挟天子→开府） | 控制汉献帝（判定方式见 Q1）+ 自主选择开府 | 霸府专属官职任命权（Q2）+ 外交权重加成（Q3）+ 伪诏宣战（Q4） | ✅ | ❌（开府即历史事件，不可撤销） |
| 2 | **称王** | 霸府状态 + 势力规模门槛（Q6）+ 自主选择称王 | 王国官职体系扩展（Q2）+ 爵位上限提升 + 外交权重再加成 | ✅ | ❌ |
| 3 | **称帝** | 称王状态 + 更高势力规模门槛（Q6）+ 自主选择称帝 + （可选）汉帝禅让/废立事件 | 帝国官职体系全开（Q2）+ 最高外交权重 + 年号/国号 | — | ❌ |

**设计原则**：
- **可选可停留**：玩家可在任意阶段停止推进，维持霸府或称王状态 indefinitely。称帝是终点，无后退。
- **不强制线性**：玩家可以不开府直接称王吗？**不可以**。称王的前置是霸府（逻辑上"王"是汉帝册封或自封的诸侯之首，不挟天子无所谓"王"）；称帝前置是称王。线性链：诸侯 → 霸府 → 王 → 帝。
- **称王称帝的额外前置**：势力规模门槛（城池数/总兵力，具体数值待 Q6 拍板），避免开局即称王。
- **后退禁令**：开霸府/称王/称帝都是历史性政治事件，一旦发生不可撤销（董卓废立、曹操称魏王都是历史节点，不可逆）。

## 四、与已有系统的接口设计

### 4.1 君主头衔变化如何影响君主特例规则

Session 188 已定稿：君主不参与忠诚度/拉拢记录/功绩系统。开霸府/称王/称帝伴随君主头衔变化时，有两种处理方式（详见 Q7）：

- **方式 A（换头不换人）**：`Faction.rulerId` 不变，君主武将实体不变，只改其头衔展示（如 `nobilityRank` 从 marquis 升 king，或新增 `hegemonyTitle` 字段）。君主特例规则自然延续，无需改动。
- **方式 B（换人头衔分离）**：引入"政治头衔"独立字段（`Faction.politicalTitle` 或 `Officer.hegemonyTitle`），与 `Faction.rulerId` 解耦。君主特例规则依然适用（头衔变了还是君主）。

**审计结论**：无论哪种方式，**君主特例规则（04 §3.8）都不需要修改**——君主不参与忠诚度/拉拢记录/功绩的原因是"君主是势力化身"，这个性质在霸府/称王/称帝后依然成立（魏王曹操依然是曹魏势力的化身）。头衔变化只是"势力化身"的称号变了，不改变"是势力化身"这一事实。

### 4.2 霸府专属官职如何接入现有官职体系

取决于 Q2 拍板。三种候选方案的接口影响：

| 方案 | 接口影响 | 改动文件 |
|:----:|------|------|
| A 扩展现有枚举 | `CivilPosition`/`MilitaryPosition` 加霸府取值（如 `GRAND_COMMANDER` 大司马、`REGENT` 录尚书事） | shared/enums + shared/positions.ts + appoint.ts + OfficerDetail UI |
| B 新增独立轨道 | `Officer.hegemonyPosition?: HegemonyPosition` 新字段，霸府状态时任命引擎支持 | shared/types/officer.ts + appoint.ts + OfficerDetail UI + 存档 schema |
| C 复用爵位轨道 | `NobilityRank` 已有 king=皇帝，称王=king、称帝=新增 emperor 或复用 king | shared/enums + 04 §5.5 爵位表扩展 |

### 4.3 外交系统需要新增什么样的修正因子

基于 §2.4 审计，外交系统扩展较容易。需要新增的修正因子类别：

| 修正类别 | 触发条件 | 影响范围 | 设计方向 |
|:----:|------|------|------|
| **霸府外交权重** | 势力处于霸府阶段 | `calculateAllianceChance` 成功率 +N、进贡/献美友好增量 ×(1+N) | 参照 04 §36.2 曹操"挟天子令诸侯"+30 外交权重 |
| **称王外交权重** | 势力处于王阶段 | 霸府修正基础上再加 | 数值待 Q3 拍板 |
| **称帝外交权重** | 势力处于帝阶段 | 最高外交权重 + 对其他未称帝势力的"天命压制"修正 | 数值待 Q3 拍板 |
| **对汉室态度匹配修正** | 双方对汉室态度 tag 匹配/冲突 | 结盟成功率 ±N（匡扶汉室势力 vs 挟天子霸府结盟难度+） | 参照 04 §36.2 刘备"对汉室势力宣战声望-30" |
| **伪诏宣战** | 霸府阶段主动能力 | 可对任意势力宣战（消耗"皇权点数"，冷却 N 季） | 参照 04 §36.2 曹操特殊能力"挟天子令诸侯：可伪诏宣战" |

export type PoliticalStage = 'vassal' | 'hegemon' | 'king' | 'emperor';

| B 政治头衔独立 | `Faction.politicalTitle?: string` 与 rulerId 解耦 | 头衔变化不动武将实体；与 politicalStage 状态机天然对应 | 新字段 |

**已批准：方案 B**。`Faction.politicalTitle` 与 `Faction.politicalStage` 一一对应（vassal→无/hegemon→"丞相/大将军"/king→"X王"/emperor→"X帝"），头衔变化只改 Faction 字段，不动 `Officer` 实体，君主特例规则完全不需要改。

### Q8 天命系统是否纳入本主线 — **已批准：HC-P2 可选增强，非 HC-P0/P1 必备**

**设计方向**：称帝势力获得"天命"值，影响外交/声望/AI 态度。天命可升降（占城+/失城-/事件±）。

**开放问题**：天命系统是否本主线必备？还是作为 HC-P2 的可选增强？如果做，数值范围与影响机制？

### Q9 禅让/废立事件链是否本主线必备 — **已批准：HC-P2 可选增强，非 HC-P0/P1 必备；称帝先只支持"自主称帝"路径**

**设计方向**：称帝路径之一是汉帝禅让（曹丕代汉模式），需要事件链支持汉帝 → 玩家势力君主 的禅让仪式。

**开放问题**：禅让是称帝的唯一路径，还是路径之一（另一条是"自主称帝"不需要禅让）？禅让事件链是否本主线必备，还是留后续？

### Q10 与 04 §36 势力特点的关系 — **已批准：分离**

04 §36.2 已设计 12 势力核心理念含"对汉室态度"维度（曹操"挟天子令诸侯"、刘备"兴复汉室"），但数据未入库。本主线的 `politicalStage` 状态机与 04 §36 势力特点是**合并**还是**分离**？

| 方案 | 描述 |
|:----:|------|
| 合并 | `FactionTrait` 接口扩 `politicalStage` 字段，势力特点与政治阶段一体 |
| 分离 | `FactionTrait` 保留 04 §36 原设计（势力性格），`politicalStage` 独立承载本主线状态机 |

**已批准：分离**。势力特点是"势力的固有性格"（曹操唯才是举是天性），政治阶段是"势力的当前状态"（曹操开局是诸侯，后来变霸府）。两者维度不同，合会引发"曹操开局就是霸府"的语义错位。

### Q11 与君主特例切片 C 的依赖关系 — **已批准：可并行**

Session 188 切片 C（引擎守卫：拒绝给君主赏赐美人/赐婚/改功绩）尚未落地。本主线的 HC-P0-4（霸府官职任命）需要 appoint.ts 支持新官职，而切片 C 也要改 appoint.ts。

**开放问题**：HC-P0 是否前置依赖切片 C？还是两者可并行（切片 C 加君主守卫 + HC-P0 加霸府官职，两者改动不冲突）？

**已批准：可并行**。切片 C 是"拒绝给君主改忠诚/功绩"，HC-P0 是"支持新官职任命"，改动点不重叠。

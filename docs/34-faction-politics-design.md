# 城级派系与门阀系统设计（S27）

> 对应 S26 之后第 27 大系统（注册 26→27 大系统，Session 285 首轮实装）。
> 关联：`04-game-systems.md`（内政/民心/战斗）、`08-data-dictionary.md` §二十一（数字真源）、`12-system-map.md`
> 实现位置：`shared/city-factions.ts`（派生/效果纯函数）+ `server/src/engine/factionPolitics.ts`（命令+月度结算）

## 一、设计定位

**城市内部的政治生态层**：在「势力-郡-城」现有行政链下，为每座城市增加内部派系满意度，
让「收买民心」不再是单一的民心数值，而是可经营、可博弈的微观政治棋盘。
同时引入**势力声望（fame）**与**兵装（arms）**两条宏观资源线，与城级派系互相咬合。

| 资源 | 本质 | 获取 | 消耗/衰减 |
|------|------|------|-----------|
| **派系满意度** | 城市内部各集团对玩家的好感 | 开垦（流民）/巡查（商贾）/施米（流民）/开发（世家/商贾） | 开垦（世家−）、巡查（小势力−）、月度回归 |
| **声望 fame** | 势力宏大声望 0~1000 | 破城+20/占城+10/灭国+50/结盟+10/施米+2 | 每季−2 |
| **兵装 arms** | 势力军备库存 | 采购 10金/件、首都+8/月、城防≥150城+2/月 | 征兵/训练/战斗消耗 |

**0-A 边界**：试点 6 城（洛阳/长安/阳翟/汝南/邺/陈留），其余城市派系为空。
名门特例：阳翟 → 颍川荀氏·颍川陈氏；汝南 → 汝南袁氏（仅出现在郡望城市）。

## 二、城级派系

### 2.1 派系种类

| 层 | 种类 | 说明 |
|----|------|------|
| 核心 | 世家 / 流民 / 商贾 | 试点城市必有 |
| 随机池 | 豪强 / 宗族 / 教团 / 官宦 / 游侠 | 每城 0~2 个（45%/35%/20%，按城市 ID 哈希） |

### 2.2 数据结构

```ts
interface CityFactionEntry {
  kind: 'aristocracy' | 'refugees' | 'merchants' | 'militia' | 'clan' | 'cult' | 'eunuchs' | 'wanderers';
  name: string;        // 名门用郡望（颍川荀氏等），其余用通称
  satisfaction: number; // 0~100，月度向 50 回归
}
// City.cityFactions?: CityFactionEntry[]  旧档缺省按城市 ID 派生
// City.factionPatrolStamp?: number         巡查时间戳（年×12+月），当月免叛乱
```

### 2.3 满意度初始值与回归

- 初始：核心 40~60；小势力 45~65（特例：官宦 15~45、豪强/宗族 55~75，Session 286 实测校准
  使弹劾/自募自然可达）；名门 60~75（确定性派生，`SerializableRng(cityId)`）。
- 月度回归：每月向 50 移动 ±1（`regressSatisfaction`）。

## 五、声望（fame）与兵装（arms）

### 5.1 声望

- 范围 0~1000，初始 100；`grantFame` 统一增减（0~1000 夹紧）。
- 获取：破城 +20 / 占城（投降） +10 / 灭国 +50 / 结盟 +10 / 施米 +2。
- 衰减：每季首月（1/4/7/10）全势力 −2。
- **叙事化标签（Session 287）**：`fameLabel`（shared 纯函数），5 档文言标签，档位边界与
  投奔阈值对齐：≥900 威震天下 / ≥600 名扬海内 / ≥300 声名鹊起 / ≥100 崭露头角 / <100 名不见经传。
  经 `/faction/overview` 返回 `fameLabel`，势力抽屉声望区展示。

### 5.2 兵装

- 获取：采购 10金/件；首都 +8/月；每座城防≥150 的城再 +2/月。
- 消耗：征兵每 100 兵 −1（名门城）；训练每次 −5；战斗损失按 0.5× 兵力损失折算。
- 战力：arms×100 ≥ 兵力（满配）→ 攻防 ×(1+5%)；缺口过半且已有库存 → ×(1−10%)。
- 实现：`armsCombatMultiplier`（shared 纯函数）+ `ArmsModifier` 接入 computePower 与 battle 初始值。

## 六、月度结算（tickFactionPolitics）

在 `advanceTurn` 城市结算后执行，纯函数：

1. **补种**：`cityFactions` 缺省（旧档）按 `deriveCityFactions(cityId)` 派生。
2. **回归**：全城满意度向 50 移动 ±1。
3. **兵装月产**：按势力聚合（首都 +8、城防≥150 的城 +2）。
4. **叛乱判定**：存在满意度 <30 的小势力且当月未巡查（`factionPatrolStamp` ≠ 当前月戳）→ 10% 叛乱；
   叛乱代价：兵力 −10%、民心 −5、不满小势力重置 50，写入 `faction_revolt` 日志。
5. **每季首月**：全势力声望 −2。

## 十、深化一：派系事件（Session 286）

> 月度结算新增「派系事件」层：满意度达到阈值时派系主动施为（正向献力 / 负向抽逃），
> 事件结果写入 actionLog（type=`faction_event`），不弹 UI 不消费玩家操作。
> 数字真源：`08-data-dictionary.md` §二十三。

### 10.1 触发规则

- 每城每月至多 1 个事件，判定顺序：
  1. **高满意度池**（任一派系满意度 ≥70）：触发概率 25%；
  2. 若未触发，**低满意度池**（核心三派系任一 <30）：触发概率 20%。
- 命中后从满足条件的派系中按 entries 顺序第一个命中，数值效果消费权威 RNG。
- RNG 消费：高池判定 1 次（未中则低池判定 1 次，最大 2 次）+ 数值 1 次。**与叛乱判定、兵装月产互不干扰**（事件在叛乱之后执行）。

### 10.2 事件表

| 派系 | 条件 | 事件名 | 效果 |
|------|------|--------|------|
| 世家 | ≥70 | 名门献金 | 城金 +30~60 |
| 流民 | ≥70 | 流民垦荒 | farm +10~25 |
| 商贾 | ≥70 | 货路繁盛 | 城金 +40~80 |
| 豪强 | ≥70 | 豪强应募 | 城兵力 +3%（至少 +20） |
| 宗族 | ≥70 | 宗族输粮 | 城粮 +50~100 |
| 教团 | ≥70 | 教团祈福 | 民心 +2 |
| 官宦 | ≥70 | 官宦引荐 | 城金 +20~40 |
| 游侠 | ≥70 | 游侠缉盗 | 守军士气 +2 |
| 世家 | <30 | 世家抽逃 | 城金 −20~40 |
| 流民 | <30 | 流民流亡 | farm −5~15 |
| 商贾 | <30 | 商贾撤资 | 城金 −30~60 |

> 随机池小势力 <30 的负面效果已由既有叛乱判定覆盖，不重复设置事件。

### 10.3 实现

- `shared/city-factions.ts`：`pickFactionEvent(entries, rng)` 纯函数（候选判定 + 选中返回
  `FactionEventOutcome { eventId, goldDelta?, farmDelta?, foodDelta?, troopsDelta?, moraleDelta? }`）。
- `server/src/engine/factionPolitics.ts` `tickFactionPolitics`：叛乱判定后执行事件层。

## 十一、深化二：弹劾机制（Session 286）

> 官宦派系不满时可对城主发动弹劾；玩家二选一处理，逾期自动平息。
> 数字真源：`08-data-dictionary.md` §二十四。

### 11.1 触发

- 条件：该城有 `eunuchs` 派系且满意度 <30，且该城有城主（`city.officers[0]` 在职且非君主）。
- 概率：每月 20%（仅在既有叛乱判定**未触发**时进行，避免同月叠加）。
- 结果：写 `City.pendingImpeachment = { officerId, sinceStamp }`，actionLog 记录 `faction_impeach`。

### 11.2 处理（POST `/civil/impeach`）

| 选项 | 条件 | 效果 |
|------|------|------|
| `appease` 安抚 | 耗金 100 | 官宦满意度 +20，弹劾消除 |
| `remove` 撤换 | 城主非君主 | 城主解职（太守解职 + 移出 `city.officers[0]` 位，调用 S12 `appointOfficer`），城主忠诚 −10，官宦满意度 +10，弹劾消除 |

### 11.3 逾期

- `pendingImpeachment` 保留 2 个月（月度 tick 计数，stamp 差 ≥2 即落空）；到期未处理 → 弹劾落空：
  官宦满意度 −5（更加不满）、城主忠诚 −2（惊扰），写日志，弹劾消除。

### 11.4 数据与 UI

- `City.pendingImpeachment?`（optional，Zod 同步，旧档兼容）。
- 乡政分面弹劾警示条（红框）+ 两按钮 + 逾期提示。

## 十二、深化三：自募武装（Session 286）

> 豪强/宗族满意度高时自募私兵；扩军不消耗金粮但消耗兵装，且满意度回吐。
> 数字真源：`08-data-dictionary.md` §二十五。

### 12.1 触发

- 条件：该城有 `militia` 或 `clan` 派系且满意度 ≥60（Session 286 实测校准，原 70 不可达）。
- 概率：每月 15%。
- 效果：城兵力 +max(20, floor(人口 ×0.005))；兵装 −3；该派系满意度 −5；
  actionLog 记录 `faction_self_recruit`。
- RNG：1（触发判定）+ 0（兵力公式确定性，不摇点）。

### 12.2 边界

- 自募武装不产生独立"私兵"字段（0-A 简化），直接并入城兵力。
- 与高满意度事件（豪强应募/宗族输粮）互斥：同一月仅取其一（事件层先判定）。

## 十三、家属处置对叛乱（Session 351）

家属处置不复制一套派系事件，而是在既有 `tickFactionPolitics` 的叛乱判定上读取城市
`familyTreatment.mode`：善待将基础每月 10% 乘以 0.7，镇压乘以 1.5，中立乘以 1.0。
巡查豁免、叛乱代价、RNG 消费顺序和派系事件顺序保持原规则。数字真源见
`docs/08-data-dictionary.md` §二十六；六角直接战斗不在本轮读取镇压攻城倍率。
